## 1. 系統總覽

### 1.1 一句話介紹

**1shop 出貨中控台** 是一個 Tampermonkey 使用者腳本(UserScript),自動化 1shop 後台的訂單分類、備註撰寫、發信、移分頁,以及多家物流(Logistics Carrier)的拋單與印單流程。

### 1.3 技術核心

- 三路徑攔截器(Three-Path Interceptor):form submit / window.open / a.click

### 2.2 元件用途與互動

#### A. 浮動掃描控制台 `#v11-fab`(永遠在頁面右下角)

| 元件 | ID | 用途 |
|---|---|---|
| 標題列(可拖曳) | `#v11-fab-drag` | 顯示版本號;按住拖移到別處 |
| 收合按鈕 | `#v11-fab-toggle` | 切換 ➖ 收合 / ➕ 展開 |
| 預購關鍵字輸入框 | `#v11-kws` | 用逗號分隔的 SKU/關鍵字,符合者歸類為預購 |
| 掃描深潛頁數 | `#v11-pages` | 1-10,從當前頁開始往後掃 N 頁 |
| 預購歸類目的地下拉 | `#v11-preorder-tab` | 預購訂單預設要移到「暫存」or「其他」分頁 |
| 啟動大數據掃描 | `#v11-btn-scan` | 主要進入點,觸發 `startScan()` |
| 開啟看板 | `#v11-btn-open-kanban` | 把掃描結果的看板 modal 展開 |

#### B. 中控台看板 modal `#v11-modal`(預設隱藏,掃描後展開)

| 元件 | ID | 用途 |
|---|---|---|
| 標題列 | `#v11-modal-drag` | 顯示版本號,可拖曳 |
| 縮小視窗 | `#v11-btn-close` | 關閉 modal 但保留資料 |
| 訂單卡片區 | `#v11-cards-container` | 6 大類型分類顯示,每張卡片內可逐筆編輯 |
| 一鍵全局批次執行 | `#v11-btn-global` | 主要動作:全部訂單跑完 A→B→C 階段 |
| 自動分流當天出貨 | `#v11-btn-only-logistics` | 只跑階段 C(物流拋印),跳過 A/B |
| 異常單預設公版 | `#v11-btn-edit-email` | 開啟公版郵件編輯 popup |
| 公版郵件 popup | `#v11-email-popup` | 編輯發信公版,分【重複單】`#v11-bsubj`/`#v11-bbody` 與【未付款催繳】`#v11-usubj`/`#v11-ubody` 兩組,存檔後發信路徑會實際讀取 |

#### C. 訂單列(每筆訂單在卡片內的一列)

每筆訂單動態 render 的 row,**沒有固定 ID**,只有 `data-order-id` 屬性。包含:
- 訂單編號(可點到 1shop 原生頁)
- 購買商品欄 `.td-product`(**★ V11.46 起**顯示 comboLabel 短標籤 `SKU*數量`,完整名在 title 屬性)
- 顧客備註圖示 / 商家備註圖示(hover 顯示內文)
- 備註輸入框 `.v11-row-note`(允許編輯)
- 發信勾選 `.v11-row-email`(只在需要發信的類型顯示)
- 移動分頁下拉 `.v11-row-move-tab`(橘色背景強調)
- **★ V11.39 新增**:分類調整下拉 `.v11-row-type`(讓使用者手動改類型)
- ✏️ 標記(已人工調整過的訂單會顯示)

#### D. 卡片底部操作區 `.v11-card-footer`(★ V11.44/45 強化)

每張卡片底部,依類型顯示不同操作:
- **NORMAL 卡片**:物流下拉 `.v11-logistics-select` + 商品組合下拉 `.v11-combo-select`(★ V11.44) + 「🚀 單獨執行本區拋單」按鈕
- **其他卡片**:「🚀 單獨執行本區動作」按鈕
- **★ V11.44**:footer 改 `position: sticky` 吸附底部,長清單滾動時操作區不跑掉
- **★ V11.45**:物流下拉改變時,商品組合下拉的 `[N筆]` 即時重算(只算該物流的訂單)

商品組合下拉(`.v11-combo-select`)細節:
- 只列「>1 筆」的組合(單筆用「全部」+ 手動勾選)
- option value 存完整 product、顯示用短 comboLabel
- 依筆數多到少排序

#### E. 進度泡泡 `#v11-progress-bubble`(執行中才出現)

- 顯示在右下角,動作執行時取代浮動控制台
- 內容:`🚀 {動作名稱} 執行中,請勿關閉視窗...`
- 結束後自動消失

#### F. Toast 通知

- 右上角短暫提示
- 4 種型別:`info`(藍)/ `success`(綠)/ `warn`(橘)/ `error`(紅)

## 3. 主要使用流程

### 3.1 標準流程:從掃描到完成

```
1. 使用者打開 admin.1shop.tw/shop/order/all
2. 浮動控制台自動出現在右下角
   ↓
3. 設定預購關鍵字 + 深潛頁數
4. 點「🤖 啟動大數據掃描」
   ↓
   ├─ 進度泡泡顯示「掃描中,請勿關閉本頁籤...」
   └─ 多頁深潛抓取訂單,寫商家備註的 hover 內文
   ↓
5. 看板自動展開(modal 出現)
   - 訂單已自動分類成 6 大類型卡片
   - DUP 已細分 KEEP / CANCEL
   ↓
6. 使用者人工微調:
   - 改備註文字
   - 改移分頁目的地(下拉)
   - 改類型(下拉 — 改 EXC 為 NORMAL 等)
   - 改發信勾選
   - ★ V11.44:NORMAL 區可用「商品組合」下拉篩選特定商品批次拋印
   - ★ V11.45:選物流下拉時,組合下拉筆數即時連動重算
   ↓
7. 點「🌟 一鍵全局批次執行」(主要動作)
   ↓
   ├─ 階段 A:寫商家備註 + 發信(逐筆;每筆前先清殘留 modal)
   │   └─ ★ V11.55 失敗隔離:寫備註或發信失敗的訂單記進失敗清單,
   │      跑完彈 alert 列出,且**不進階段 B/C**,原地留在等待確認分頁
   ├─ 階段 B:批次移分頁(依使用者選擇的目的地;已排除失敗筆)
   └─ 階段 C:多家物流拋單 + 印單(7-11 → 全家 → 宅配;已排除失敗筆)
   ↓
8. 結束後:
   - 進度泡泡消失
   - ★ V11.43 起:**不會自動展開看板**,維持縮小狀態
   - Toast 通知「✅ ... 完成(中控台保持縮小,點浮動按鈕可展開看板)」
   - ★ V11.42 起:**不會自動重新掃描**,需要使用者手動點掃描更新看板
   ↓
9. 物流單在背景分頁:
   - 7-11 / 全家 / 宅配 的物流單分頁在 Chrome 分頁列存在
   - 使用者要看時自己切過去,Ctrl+P 列印
```

### 3.2 快捷流程:只拋印當天訂單

當天的訂單都在「處理中 / 已確認」分頁,不需要再過階段 A/B 時:
- 點「🚀 自動分流當天出貨」→ 直接跑階段 C

### 3.3 跨頁續航流程

- 當階段 C 需要切到別的分頁(例如「已確認」)拋印
- 1shop 切分頁會強制 reload 頁面 → 腳本記憶體狀態消失
- 腳本用 `localStorage` 存 `RESUME_FLAG` + `RESUME_PAYLOAD`
- 頁面重載後:腳本啟動時偵測 RESUME_FLAG 存在 → 自動接續流程

## 4. 訂單分類規則

### 4.1 6 大類型(優先順序由高到低)

| 順序 | 類型 | 中文名 | 預設備註 | 預設移分頁 | 預設發信 |
|---|---|---|---|---|---|
| 1 | `DUP` | 🔴 重複異常單 | (細分如下) | (細分如下) | (細分如下) |
| 2 | `UNPAID` | 🚨 未付款提醒單 | 提醒付款 | 確認中 | ✅ |
| 2b | `UNPAID` + `payUnknown` | ⚠️ 付款狀態未收錄 | 付款狀態待確認 | 確認中 | ✗ |
| 3 | `PREORDER` | 🟡 預購品 | 預購品處理中 | 暫存 / 其他 | ✗ |
| 4 | `EXC` | 🔵 EXC 訂單 | 待折抵 | 確認中 | ✗ |
| 5 | `OVERSEAS` | ✈️ 海外單 | 海外單 | 確認中 | ✗ |
| 6 | `NORMAL` | 🟢 可出貨一般單 | (空白) | 不移動 | ✗ |

訂單會走第一個符合條件的類型,例如同時是預購+重複,會被分到 DUP(優先序高)。

### 4.1b 付款狀態如何決定 UNPAID / NORMAL（★ V11.56 白名單）

依 `A 平台事實` P12／P13，判定只比對 `.status-name`（不含天數／次數徽章）：

判定用**整格文字**做包含比對（一格內有交易管道＋金流狀態＋附註三段），
**順序即優先序，不可調換**：

| 順位 | 分組 | 狀態字串 | 歸類 |
|---|---|---|---|
| 1 | 已退款 | 已退款 | `UNPAID` + `payRefunded`，**不出貨、不發信**，備註「已退款 待確認」 |
| 2 | 不會完成 | 付款失敗、交易逾時、交易取消 | `UNPAID` 催繳（對話定版 2026-08-19） |
| 3 | 貨到付款 | 貨到付款、超商取貨時付款 | `NORMAL` 可出貨 |
| 4 | 已完成付款 | 交易成功、已付款 | `NORMAL` 可出貨 |
| 5 | 還可能完成 | 等待付款、待確認付款、未付款 | `UNPAID` 催繳 |
| 6 | **未收錄** | 以上都沒命中 | `UNPAID` + `payUnknown`，**不出貨、不發信**、掃完彈 alert 要求回報 |

> **為什麼順序不能調**：同一格可能同時出現兩個狀態字樣。
> 「已退款」排第 1 是因為退款發生在交易成功之後（同格常並存「交易成功」），晚判就會誤出貨。
> 「貨到付款」排在「等待付款」之前，是因為貨到付款的本質就是還沒付 ——
> 順序錯了，**所有貨到付款單都會被擋著並寄催繳信**。
>
> **永遠不要比對交易管道**（LINE Pay／信用卡／ATM轉帳／信用卡 N 期0利率…）：
> 管道是開放清單，分期期數還會變動，寫死就會漏。

> **只列「可出貨白名單」，不列「不可出貨黑名單」。** V11.55 以前是黑名單思維，
> 結果「付款失敗／交易逾時／交易取消」三種狀態全部落空、被歸成可出貨一般單並自動拋單出貨。
> 成本不對稱：黑名單漏一個是把貨寄給沒付錢的人，白名單漏一個只是多一筆人工。

### 4.2 DUP 細分(同一顧客多筆訂單)

**規則只有一條（★ V11.56）**：會成立的付款「恰好 1 筆」→ 保留那筆並發信、其餘取消；
其他一切（0 筆、或 2 筆以上會成立）→ 全部不發信、交客服。

| 子類 (`dupRole`) | 何時指派 | 預設備註 | 預設移分頁 | 預設發信 | 發信公版 |
|---|---|---|---|---|---|
| `KEEP` | 整組**恰好 1 筆**會成立付款時，那一筆 | (空白) | **不移動**(★ V11.41 從「已確認」改) | ✅ | 重複單公版 |
| `CANCEL` | 同上情況下的其餘筆 | 重複訂單 此筆取消 | 已取消 | ✗ | (擋下) |
| `PENDING` | 0 筆會成立、或 2 筆以上會成立 | 重複訂單 幫關心 | 確認中 | ✗ | (擋下) |

> `UNPAID_DUP` 已於 V11.56 退役（沒有任何情境會指派它）。
> **2 筆以上會成立也走 `PENDING`**：兩筆都刷卡成功＝錢收了兩筆，涉及退款，
> 把訂單移到「已取消」不等於處理完；自動寄「已幫您取消」但錢沒退會造成客訴。
> **0 筆會成立也走 `PENDING`**：沒有依據判定要保留哪一筆。

原本的 A/B/C/D/E 五情境分支已於 V11.56 收斂成上面那一條規則，由 `judgeDupGroup` 單一判定。
看板上的診斷字串也改由同一個判定產生 —— 舊版兩個函式各算一次，漂移出「看板寫『不發信』
但實際寄了信」「看板寫『重複未付款』但兩筆其實都刷卡成功」兩種說一套做一套。

### 4.3 人工分類調整(V11.39 新增)

每張訂單列右側有「分類下拉」(橘色背景),使用者可:
- 把 EXC 改成 NORMAL(備註保留「待折抵」,但走 NORMAL 拋印流程)
- 把 NORMAL 改成 EXC
- 等等任意 6 大類型切換

調整後該訂單會:
1. 自動移到新類型的卡片
2. 套用新類型的「預設移分頁 + 發信規則」
3. **保留**原備註文字(不會被新類型的預設備註覆蓋)
4. 顯示 ✏️ 標記
5. 只影響當次掃描,重新掃描後恢復自動分類

### 5.2 物流拋印流程(階段 C 內部)

每家物流獨立執行:

```
1. 切到該物流的「拋單後分頁」(例如 7-11 走「已確認」)
2. 找拋單區段(matching provider 文字)
3. 全選 thead checkbox
4. 點「更多批次功能」→ 拋單按鈕
   ├─ 7-11/全家:直接執行
   └─ 宅配:跳二次確認 → 點確認
5. 點印單按鈕 → 開啟列印彈窗
6. 點最終列印按鈕(例如「7-ELEVEN大宗B2C」)
   ├─ 觸發 window.open or <a target="_blank">
   ├─ 攔截器抓到 URL,return null 阻止原生開新分頁
   ├─ 派發 v11-open-bg-tab CustomEvent
   ├─ Sandbox 收到 → GM_openInTab(url, { active: false })
   └─ 1shop 內部判定彈窗被擋 → 跳「無法另開視窗」警告
       └─ Modal Killer 偵測到 → 秒點 X 關閉
7. waitFor(lastOpenBgTabTime > t0, 25 秒)
   ├─ 攔截成功 → 立刻繼續
   └─ 25 秒沒攔到 → log warning 後繼續
8. 關閉列印彈窗
9. ★ V11.48 跨頁:findNextPageBtn 找下一頁
   ├─ 找到 → 點擊翻到下一頁,回到步驟 3 繼續拋印
   └─ 真的最後一頁(父 li .disabled)→ 結束該物流
10. 換下一家物流
```

> **★ V11.48 註記**:跨頁翻頁的可見性判斷(findNextPageBtn / findFirstPageBtn)
> 用 offsetParent===null,非 getBoundingClientRect().width。
> 原因:1shop 分頁列 angle-right 按鈕 width 會量到 0 被誤判「最後一頁」,
> 導致 50+ 筆(多頁)時只處理第一頁。

> **⚠️ 已知未解(問題 1)**:重複單(DUP)若跨頁,目前只能配對「當前頁內」的重複,
> 跨頁的重複配對尚未實作,留待後續版本。

```javascript
  // ...其他從 1shop 抓的欄位
}
```

### 6.2 主要狀態流轉

```
[掃描階段]
allOrders = []                     ← 全域陣列
  ↓ startScan()
allOrders = [...掃描結果]
  ↓ classifyOrders()
allOrders 每筆 .type / .dupRole 被填入
  ↓ applyTypeDefaults()
allOrders 每筆 .rowNote / .rowMoveTab / .needEmail 被填入預設值
  ↓ renderKanban()
看板 modal 展開,訂單以卡片呈現
  ↓
[使用者編輯階段]
直接修改 DOM 上的 input / select / checkbox
  ↓ saveRowInputsToData() (執行前)
allOrders 同步 UI 上的編輯
  ↓
[執行階段]
runFullPipeline('global') 或 runLogisticsOnly()
  ↓
階段 A → 階段 B → 階段 C
```
