### V11.55 細列

| # | 問題（現象 → 原因 → 影響） | 修法 |
|---|---|---|
| ① | **根因。** 寄信框跳出來又自己關掉、信沒寄出（現象）→ 平台內文框是 `body_code`，腳本指紋寫 `body`，主旨填得進去、內文永遠 `waitFor` 逾時（原因）→ 客人完全沒收到通知，整整一版沒被發現（影響） | 指紋加入 `body_code`，新舊並存；內文等待 800ms → 2500ms 與主旨一致。事實入 A 表 P10 |
| ② | **靜默失敗。** 客人沒收到信、備註沒寫進去，訂單卻照樣被移分頁出貨（現象）→ 階段 A 沒接 `processNoteForOrder` / `sendEmailForOrder` 的回傳值，失敗只寫 `console.warn`（原因）→ 系統狀態與客人認知對不起來，畫面顯示「✅ 全流程完成」，事後查不出是哪幾筆（影響） | 失敗進清單、跳 toast、跑完彈 alert 列出；**失敗筆不進階段 B/C**，原地留在等待確認分頁。每筆處理前先 `forceCloseAllModals` 斷開連鎖失敗 |
| ③ | **公版沒接線。** 在 popup 改公版、按了儲存，寄出去的信完全沒變（現象）→ popup 寫進 localStorage 之後沒有任何人讀它，發信只用程式內建常數（原因）→ 使用者以為改好了（影響）。附帶：卡片編輯框永遠預填非空，把「取消筆不發信」閘門整條繞過，這是 CANCEL 筆會跳信框的原因 | 新增 `getStoredTemplate`，公版來源改為 popup 存檔值優先；popup 拆【重複單】【未付款催繳】兩組；卡片編輯框只在內容與存檔公版不同時才算覆寫 |
| ④ | **死碼。** `dupRole` 的 `UNPAID_DUP` / `PENDING` 從未被指派，看板標籤與公版分支都跑不到（現象）→ 舊版「沒有成功筆就用 ID 最大的當保留」（原因）→ 兩筆都還沒付款時，客人收到「已幫您取消，只保留下訂成功的那筆」，但根本沒有成功的那筆（影響） | 補上實際指派條件：整組全貨到付款／全純未付款 → `PENDING` 不發信；混合未付款 → 未付款筆 `UNPAID_DUP` 收催繳信，其餘 `PENDING` |
