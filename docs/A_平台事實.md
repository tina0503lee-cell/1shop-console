> **適用場景**：任何要動到 1shop 平台互動的改動之前，**強制先讀本檔**。包含勾選、拋單、印單、翻頁、分頁移動、按鈕查找、可見性判斷。
> **不處理**：UI 元件位置與自家流程設計（→ B UI 骨架）；驗收條件（→ C BDD 現行規格）；版本沿革（→ Notion 版本日誌）
> **前置依賴**：無。本檔是所有平台相關改動的前置。
> **共用參照**：術語與常數

## 本檔的地位（最高優先規則）

本檔是 1shop 平台行為的**唯一權威**。這些事實全部是用真實生產環境測試換來的，不是文件推導、不是合理推論。

**三條硬規則：**

1. **表內有的，照表做。** 不重新推論、不「我覺得應該是」。
2. **表內沒有的，就是不知道。** 遇到未收錄的平台行為，停下來明確回報缺口，等 Tina 用真實訂單實測確認後才動 code。**禁止用推論當事實往下寫。**
3. **新確認的事實，先寫進本檔再寫 code。** 事實入檔 → 才改實作 → 才更新 C BDD 現行規格。順序反了就會產生影子表。

> 這條紀律是踩過坑換來的：「移走後會不會遞補」曾被 AI 當成合理推論寫進計畫，實測結果與推論相反。平台行為的錯誤假設會一路污染下游所有實作。

## 一、已驗證平台事實

| # | 事實 | 驗證來源 | 影響 |
|---|---|---|---|

| P2 | **拋單與印單皆由 1shop 端依物流過濾**：點「711 拋單」只拋 711 單，點「711 物流單列印」只出 711 標籤 | V11.52 實測 | 程式即使勾選整個分頁所有列，也**不會拋錯家、印錯標籤或重複** |
| P3 | 拋印 log「共拋 N 筆」= **勾選數，非實際拋單數**，會偏高 | P1+P2 推得，已實測 | 純顯示語意，不影響出貨。可接受 |
| P4 | **拋單 / 印單完成後，該批 checkbox 仍保持勾選**（不自動取消） | V11.50-52 實測 | 分批時若不主動取消，下批會把「前批＋新批」一起印 → 重複印單 |

| P6 | **「更多批次功能」按鈕由 Vue 動態渲染，0 勾選時不存在** | V11.54 實測 | 取消勾選後按鈕消失，重新勾選後才重繪 |
| P7 | **勾選狀態變更後，Vue 重繪按鈕需要時間**（實測約需數秒緩衝） | V11.54，63 筆跨兩頁測試 | 一次性 `findBtnByText` 抓不到即放棄 → 第 2 批靜默失敗 |
| P8 | 某些按鈕的 `getBoundingClientRect().width` 會量到 **0（誤判為隱藏）但實際可見** | V11.47 / V11.48 實測 | 「按鈕明明在但腳本找不到」優先懷疑這個 |
| P9 | **已確認分頁拋印完，訂單留在原分頁不移走** | V11.54 實測 | 與「等待確認 → 分流」那步會移走**不同**，勿混淆 |
| P10 | **寄信 modal 的內文框是 `name="body_code" id="body_code"`**（不是 `body`）。主旨框為 `name="subject" id="subject"` | 2026-08-18 Tina F12 實測 | 舊指紋 `textarea#body, textarea[name="body"]` 永遠抓不到 → 主旨找得到、內文逾時 → 整筆發信靜默失敗並關閉 modal |

## 二、由事實推導的工程通則

這四條是上表的直接後果，寫 code 時當守則用：

| 通則 | 依據 | 做法 |
|---|---|---|
| **可見性判斷一律用 `offsetParent === null`** | P8 | 不用 `getBoundingClientRect().width === 0`。只有真正 `display:none` 才排除 |
| **任何「需勾選才出現」的元素，一律 `waitFor` 等渲染** | P6 + P7 | 禁止一次性查詢。目前 `tryThrowAction` / `doPrintAction` 皆已改為 `waitFor`（4 秒） |
| **分批操作後主動取消該批勾選** | P4 | 用 `batchIds` 重新掃 DOM、對照訂單號**精準取消這批**，從源頭斷開累積（方法 B） |
| **逐筆勾選 ＋ 重試清殘留，不依賴全選** | P5 | 批次開始前的殘留清除跑重試 3 輪 |

## 三、已被推翻的錯誤假設（禁止復活）

| 錯誤假設 | 實際情況 | 教訓 |
|---|---|---|
| 訂單移走後，下方訂單會遞補上來 | 經 Tina 明確推翻 | 平台的列表行為不可用「一般網頁應該會…」推論 |
| 拋印完成後平台會自動清空勾選 | P4：仍保持勾選 | 「完成」不等於「重置」 |
| 找不到按鈕 = 按鈕不存在 | P6/P7：可能只是還沒渲染完 | 找不到先懷疑時序，不要先懷疑存在性 |
